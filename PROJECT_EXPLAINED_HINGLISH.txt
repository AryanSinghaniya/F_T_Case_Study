1. YE PROJECT HAI KYA?
================================================================================

India mein freight (trucking) ka kaam bahut bada hai. Har hafte hazaron trucks
7 alag-alag routes pe maal dhote hain — Mumbai se Pune, Delhi se Jaipur, etc.

Problem yeh hai ki in trucks ki cost (freight cost) kabhi kabhi ACHANAK bahut
zyada ho jaati hai. Kabhi flooding se, kabhi festival se, kabhi diesel prices
se. Ye samajhna mushkil hota hai ki:

  - Cost spike natural reason se tha? (flood, festival)
  - Ya koi galat kaam ho raha hai? (overcharging)

IS PROJECT KA KAAM:
  Har hafte har route ka cost automatically check karo.
  Agar cost zyada hai, toh explain karo kyun — notes ke basis par.
  Agar koi reason nahi mila, toh flag karo human review ke liye.

OUTPUT mein milta hai:
  "Delhi-Jaipur, Nov 2024 mein +35% cost spike — KOI REASON NAHI MILA ⚠️"
  "Ahmedabad-Mumbai, Jan 2025 mein +29% cost spike — Festival surcharge ✅"

3. KONSI TECHNOLOGY USE KI AUR KYU?
================================================================================

--- A) PYTHON (Core Language) ---
KYU: Data science ke liye best language. Fast, readable, aur sab libraries
     freely available hain.

--- B) PANDAS (Data Processing) ---
KYU: CSV data load karna, grouping, aggregation — sab pandas se hota hai.
     2940 rows ko hafte-ke-hisaab se group karna, average nikalna — ye sab
     pandas mein 2-3 lines mein ho jaata hai.

KAISE USE KIA:
  - Har route ka har hafte ka "cost per tonne-km" nikala
  - Formula: SUM(total cost) ÷ SUM(weight × distance)
  - Har route ka "past 8 weeks ka average" nikala (no future data leak!)
  - Doosre similar routes se compare kiya (peer baseline)

--- C) SCIKIT-LEARN (TF-IDF Fallback) ---
KYU: Jab notes retrieve karne hote hain, toh text similarity ke liye use kiya.
     Ye ek "backup" retriever hai agar ChromaDB nahi chale.

--- D) CHROMADB (Vector Database) --- ⭐ MAIN AI FEATURE
KYU: Brief mein explicitly likha tha "use a vector database".
     ChromaDB ek vector store hai — text ko numbers (embeddings) mein convert
     karta hai, phir similarity se dhundta hai.

KAISE KAAM KARTA HAI:
  1. Har note (e.g., "flooding on Chennai-Bangalore") ko 384-dimensional
     vector mein convert kiya using all-MiniLM-L6-v2 model.
  2. Jab koi route flag hota hai (e.g., Chennai-Bangalore, March 2025),
     uska query vector banate hain.
  3. ChromaDB dhundta hai: "Kaunsa note is query se sabse zyada similar hai?"
  4. Top-k notes return karte hain for validation.

--- E) SENTENCE-TRANSFORMERS (AI Embeddings) ---
KYU: "all-MiniLM-L6-v2" model use kiya — ye ek pre-trained AI model hai jo
     text ko vectors mein convert karta hai.
     Isse "semantic search" hota hai — exact words match nahi hone chahiye,
     MEANING match honi chahiye.

EXAMPLE:
  Query: "Chennai-Bangalore route mein March 2025 cost badha"
  Note:  "Heavy flooding on Chennai-Bangalore highway disrupted truck movement"
  Match: HIGH — flood = cost increase on same route!

--- F) VALIDATION LAYER (Custom Code) --- ⭐ SABSE IMPORTANT
KYU: AI ka dhundha hua note blindly trust nahi kar sakte. Isliye CODE se
     3 conditions check karte hain:
  1. Note us ROUTE pe apply hota hai? (Chennai-Bangalore = Chennai-Bangalore ✓)
  2. Note us WEEK ko cover karta hai? (week of Feb 24 = Feb 24 to Mar 8 ✓)
  3. Note "increase" direction mein hai? (flooding = increase ✓)
  Teeno haan → "No (justified)" verdict
  Koi bhi nahi → "Yes" (unexplained, human review chahiye)

--- G) GUARDRAILS (Custom Code) ---
KYU: Pipeline ke end mein ek aur check — agar koi justified row galat verdict
     deta hai toh pipeline CRASH kar deta hai (silently wrong nahi deta).
     Ye interviewer ko show karne ke liye best thing hai!

--- H) STREAMLIT (Dashboard / UI) ---
KYU: Python se seedha web app banana aur free mein deploy karna.
     Ek .py file likhi — automatically browser mein UI ban gaya.
     Streamlit Cloud par free deploy bhi ho gaya.

--- I) PYTEST (Testing) ---
KYU: 20 automated tests likhay — unit tests aur adversarial tests.
     Adversarial = "galat route de, wrong date de — phir bhi sahi verdict aana chahiye"

--- J) GIT + GITHUB (Version Control) ---
KYU: Code ka history rakha, aur public repo se Streamlit Cloud deploy kiya.

4. PIPELINE KAISA KAAM KARTA HAI? (Step by Step)
================================================================================

STEP 1 — DATA LOAD
  shipment_records.csv load karo
  Dates parse karo, routes banao (Mumbai-Pune), weeks calculate karo (Monday)

STEP 2 — WEEKLY METRICS
  Har route + har hafte ke liye ek row:
  cost_per_tonne_km = Total Cost / (Total Weight × Total Distance)

STEP 3 — BASELINES
  A) OWN HISTORY: Pichle 8 hafte ka average (sirf purana data, koi future leak nahi)
  B) PEER: Is hafte doosre similar routes ka average (e.g., doosra Medium-type route)

STEP 4 — FLAGGING
  Agar cost > own average +15% OR peer average +20% → CANDIDATE hai
  Result: 728 weeks check kiye, 20 candidates mile

STEP 5 — RETRIEVAL (ChromaDB)
  Har candidate ke liye: "Kaunsa note relevant hai?"
  ChromaDB query karo → top-k notes return karo (similarity score ke saath)

STEP 6 — VALIDATION (Code, not AI!)
  Har note ke liye 3 conditions check karo
  Agar pass → "No (justified)", note ID save karo
  Agar fail → "Yes" (unexplained)

STEP 7 — EXPLANATION
  Justified rows: LLM se ek sentence likhwao (ya template use karo)
  Unexplained rows: Deterministic template — "No reason found, review needed"

STEP 8 — GUARDRAILS
  Final check: Har justified row ko dobara validate karo
  Koi galti → Pipeline crash (loudly, silently nahi)

STEP 9 — OUTPUT
  output.csv likho — 20 rows, 8 columns

RESULT:
  No (justified): 16 rows (N003 diesel, N001 flood, N002 festival)
  Yes (unexplained): 4 rows (Delhi-Jaipur Nov 2024, Chennai-Bangalore Mar 2025)

7. SPECIAL NOTES (INTERVIEW MEIN KAM AANE WALI BAATEIN)
================================================================================

Q: Mumbai-Pune 2025-09-15 sample output se alag kyun hai?
A: Sample output mein "Yes" (unexplained) hai. Mere output mein "No (justified)"
   hai. Reason: N003 (diesel price rise, May 2025) mein koi end date nahi hai —
   matlab open-ended. Isliye May 2025 ke baad sab Mumbai-Pune weeks cover hote
   hain. Ye logic consistent hai aur defensible hai.

Q: LLM kya karta hai is project mein?
A: Sirf ek kaam — plain English reason likhta hai. Verdict (Yes/No) KABHI
   NAHI deta. Verdict 100% code decide karta hai. Agar LLM nahi hai, toh
   template use hota hai — aur output SAME rehta hai!

Q: Eval score 100% hai — ye fake hai kya?
A: Labels maine khud banaye hain. Ye 100% score expected hai kyunki main
   apne hi labels ke against test kar raha hoon. Ye eval "infrastructure" test
   karta hai — kya pipeline sahi column format mein output deta hai? Production
   mein independent labels chahiye honge.

Q: Reproducibility kaise prove ki?
A: repro_check.ps1 chalao — pipeline 3 baar chalata hai, teeno outputs
   byte-identical hain. Reason: LLM nahi use kiya (LLM_PROVIDER=none), aur
   pandas operations deterministic hain same data par.
